Déployer un serveur GLPI

Installer une application de gestion de parc sur une machine virtuelle Linux et préparer son accès web.

Debian 12VMwareApacheMariaDBPHP

Formation · environnement de TP · Synthèse de la documentation initiale · Date de réalisation à préciser

01. Contexte & objectif

Disposer d’un service centralisé pour la gestion du parc et des demandes. Une seconde variante de la procédure décrit un déploiement sur une VM Ubuntu dans Azure, accessible en SSH par clé.

02. Environnement documenté

VM Debian 12 sous VMware · 2 Go de RAM · disque de 20 Go · pile Apache, MariaDB et PHP. La version exacte de GLPI n’est pas renseignée dans le document initial.

03. Démarche décrite

  1. Préparer la machine virtuelle et les dépendances de la pile web.
  2. Créer une base MariaDB et un compte applicatif dédié.
  3. Configurer le serveur web et lancer l’assistant d’installation de GLPI.
  4. Documenter la variante Ubuntu sur Azure et l’accès SSH par clé.

04. Plan de vérification

  • Vérifier l’état des services Apache et MariaDB.
  • Contrôler la cohérence entre l’URL, le VirtualHost et le répertoire web exposé.
  • Ouvrir l’interface GLPI et vérifier les prérequis de l’application.

Ces contrôles sont à joindre au dossier avec leurs résultats ; ils ne constituent pas un compte rendu de tests exécutés.

Contrôles Linux · exemples à adapter

systemctl is-active apache2 mariadb
apache2ctl configtest
php -v

Attendus : services actifs, syntaxe Apache valide et version PHP compatible avec la version GLPI choisie. Ces commandes ne prouvent pas une installation aboutie à elles seules. Exemples de vérification, non exécutés par ce portfolio.

05. Livrables & résultats

Procédure d’installation fournie et reformulée. Captures, versions exactes, date de réalisation et journaux de validation à joindre.

Contribution personnelle : les documents décrivent une démarche ; le rôle exact, les dates et le périmètre individuel restent à préciser avant l’oral.

Point de vigilance technique

Pour une configuration GLPI 10.0.7 ou ultérieure correspondant à la documentation officielle, la racine web doit pointer sur le répertoire public. La compatibilité des versions et les droits des répertoires sont à vérifier avant une nouvelle installation.
